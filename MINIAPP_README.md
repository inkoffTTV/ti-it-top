# TI:IT TOP Mini App 3.0

## Что добавлено
- Общий чат внутри Mini App: сообщения, Enter для отправки, автообновление, ограничение спама, серверная валидация и удаление сообщений администраторами.
- Лента событий: создание команд, заявки, решения по заявкам, решения по MMR, обращения и ответы поддержки.
- Персональные уведомления: приглашения, проверка MMR, решения по заявкам, ответы поддержки; прочитать одно/все.
- Полноценное управление несколькими администраторами:
  - добавление по Telegram ID прямо из Mini App;
  - список администраторов;
  - удаление администратора с защитой от удаления самого себя и последнего админа;
  - новые админы сохраняются в БД и переживают перезапуск;
  - `ADMIN_IDS` остаётся bootstrap-списком.
- В Telegram-админке добавлен отдельный раздел «🛡 Администраторы».
- Исправлен динамический back-навигационный binding в админке.
- Исправлен поиск команд в админке — запрос реально передаётся на сервер.
- В поддержке добавлены фильтры OPEN / ANSWERED / CLOSED.
- Проведён статический аудит API ↔ Mini App: зарегистрированные endpoints сопоставлены с используемыми фронтендом.

## Существующее
- Полная админка: пользователи, команды, турниры, заявки, проверки, поддержка, рассылка, статистика, диагностика.
- Аватар команды через Telegram file_id.
- Glassmorphism и ненавязчивые анимации.
- Точные rank assets и русские названия рангов.
- Exact MMR не блокируется справочным диапазоном OpenDota по умолчанию.

## Администраторы
`ADMIN_IDS` используется как стартовый список. После запуска значения синхронизируются с таблицей `admin_users`. Администраторы, добавленные через Mini App, сохраняются в БД.

Важно: если Telegram ID остаётся в `ADMIN_IDS`, он будет автоматически восстановлен при следующем запуске — это намеренно сделано как bootstrap-механизм.

## Зависимости
Для Mini App и async SQLite нужны `python-multipart` и `aiosqlite`; они указаны в `requirements.txt`.


## Mini App 3.1 — AI и устойчивый вывод

- Добавлен админский AI-помощник `/api/admin/ai/ask`.
- AI получает свежий снимок операционных данных БД перед каждым запросом.
- Контекст включает пользователей, профили, команды, составы, турниры, заявки, приглашения, проверки, чат, события, уведомления и поддержку.
- API-ключи, токены и Telegram initData в AI-контекст не передаются.
- AI работает через OpenAI-compatible endpoint; по умолчанию настроен `openrouter/free`.
- AI доступна только администраторам, чтобы не раскрывать данные пользователей обычным участникам.
- Исправлен вывод ошибок FastAPI/Pydantic: массивы и объекты теперь отображаются как JSON, а не `[object Object]`.
- `esc()` также безопасно форматирует массивы/объекты при рендеринге.
- Поиск команд в админке теперь реально передаёт `q` на сервер.

### .env

```env
AI_API_KEY=
AI_BASE_URL=https://openrouter.ai/api/v1/chat/completions
AI_MODEL=openrouter/free
```

## Mini App 3.2 — AI DB Agent

AI-помощник теперь работает как read-only агент с 18 серверными инструментами. Модель не получает прямого доступа к БД: она запрашивает только нужные сведения, а сервер выполняет безопасные SQL-запросы и возвращает ограниченный JSON-результат.

Покрываются все основные ORM-таблицы проекта: пользователи, профили, команды и составы, RankRange, турниры, заявки, приглашения, поддержка, рассылки, администраторы, чат, события, уведомления и журнал проверок. Для широкого анализа есть отдельный ограниченный full snapshot tool.

### Рекомендуемая бесплатная настройка

```env
AI_API_KEY=YOUR_OPENROUTER_KEY
AI_BASE_URL=https://openrouter.ai/api/v1/chat/completions
AI_MODEL=openrouter/free
AI_MAX_TOOL_ROUNDS=5
```

### Альтернатива: Gemini через Google AI Studio

```env
AI_API_KEY=YOUR_GEMINI_KEY
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
AI_MODEL=gemini-3.8-flash
AI_MAX_TOOL_ROUNDS=5
```

Не указывай ключи в Git, README или скриншотах; ключ хранится только в `.env`.


## Mini App 3.3 — бесплатный AI fallback для РФ/VPN
- Основной AI: OpenRouter Free Router.
- Второй вариант без второго ключа: `qwen/qwen3.8-27b:free`.
- Независимый резерв: Groq `openai/gpt-oss-120b` через `AI_BACKUP_API_KEY`.
- Все AI-запросы используют `HTTP_PROXY_URL`, поэтому можно направить их через уже настроенный VPN/HTTP proxy.
- Admin API показывает состояние провайдеров и факт наличия proxy без раскрытия секретов.


## Mini App 3.4 — исправлена загрузка аватаров
- Mini App больше не создаёт отдельный Telegram Bot API client без proxy: все вспомогательные вызовы Bot API используют `HTTP_PROXY_URL`.
- Аватар сначала валидируется и нормализуется сервером в JPEG до 512 px, после чего сохраняется в `miniapp/data/team_avatars/`.
- Поэтому веб-аватарка продолжает работать даже при 403/522/сетевой недоступности Telegram Bot API.
- Telegram `file_id` остаётся дополнительной копией для показа аватарки в сообщениях бота. Если Bot API недоступен, upload всё равно считается успешным для Mini App.
- Добавлен fallback показа локальной аватарки и в Telegram-команде «Моя команда».
- После загрузки фронтенд показывает, удалось ли также загрузить копию в Telegram.
- Перезаписываемый файл хранится по `miniapp/data/team_avatars/team_<ID>.jpg`; папка добавлена в `.gitignore`, чтобы пользовательские аватарки не попадали в репозиторий.
- Для максимальной совместимости рекомендуется JPG/PNG/WebP/GIF; HEIC может зависеть от того, умеет ли установленный Pillow декодировать этот формат.

### Важное для РФ/VPN
В `.env` должно быть указано то же значение прокси, через которое уже работает Telegram/остальные внешние запросы, например:
```env
HTTP_PROXY_URL=http://127.0.0.1:10808
```
Если Telegram API доступен только через VPN, Mini App upload не пытается обращаться к нему напрямую.

## 4.0 — полный UI rewrite + hybrid 16-team playoff seeding

- Mini App полностью переработан в mobile-first интерфейс: единая визуальная система, нормальная иерархия карточек, компактная нижняя навигация, адаптивные формы и состояния загрузки/ошибок.
- Турниры получили полноценную страницу деталей: состав поля, статус заявки и визуальную playoff-сетку.
- Для турнира на 16 команд добавлен hybrid seeding:
  - администратор вручную назначает seed #1 и seed #2;
  - остальные 14 одобренных команд автоматически сортируются по среднему подтверждённому MMR и получают seed #3–#16;
  - используется стандартная 16-team схема первого раунда: 1×16, 8×9, 4×13, 5×12, 2×15, 7×10, 3×14, 6×11.
- Для посева используются только подтверждённые значения `approved_mmr` / `exact_mmr` при `mmr_verified=true`. Отсутствующий MMR никогда не заменяется рангом или расчётным значением.
- Сетка хранится отдельно от SQLite в `runtime/brackets/tournament_<ID>.json`. Схема `tournament.db` не меняется.
- Перед фиксацией сетки проверяется полнота MMR: для каждой команды требуется минимум 5 подтверждённых игроков.
- После генерации вычисляется сигнатура данных команд. При изменении состава/подтверждённого MMR интерфейс помечает сетку как устаревшую; зафиксированная сетка не перестраивается автоматически.
- Убрано ложное вычисление количества матчей из часов Dota 2. Если реального источника матчей нет, UI показывает `—`.
